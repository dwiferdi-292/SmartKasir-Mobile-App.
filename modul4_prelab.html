TEST DOUBLE IMPLEMENTATION

Implement at least two different types of Test Double:

Test Double Type Purpose Reason for Selection
Test Double 1 Stub Menyimulasikan pengecekan sisa stok produk pada tabel inventaris tanpa melakukan koneksi query ke server database MySQL nyata. Mengisolasi unit testing dari dependensi I/O database, membuat pengujian berjalan lebih cepat, deterministik, dan dapat menyimulasikan skenario stok habis (0) secara konsisten.
Test Double 2 Mock Memverifikasi bahwa method logStockMutation() dan reduceInventory() dipanggil tepat 1 kali dengan parameter item ID dan kuantitas yang sesuai saat checkout berhasil. Memastikan interaksi komunikasi antar komponen pencatatan audit log mutasi stok berjalan tepat tanpa harus menuliskan data sampah ke tabel log riwayat produksi.

Notes: Pemilihan Stub dan Mock secara efektif memisahkan logika validasi bisnis transaksi kasir dari persistensi database dan sistem eksternal, sehingga kesalahan yang muncul murni berasal dari kecacatan logika unit tersebut (defect isolation).
